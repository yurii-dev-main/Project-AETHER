# Unity workflow reference for this repo

## Общие правила структуры скриптов
- Каждый `MonoBehaviour` содержит только поля, методы и вложенные типы внутри тела класса.
- Никаких операторов `if`, `for`, `while` и т.д. на верхнем уровне файла (только внутри методов).
- Закрывающие фигурные скобки должны соответствовать вложенности: `namespace` -> `class` -> `method`.

## Инициализация и жизненный цикл
- Использовать `Awake()` для:
  - настройки синглтонов (например, `DungeonManager.Instance`).
  - привязки к данным, которые должны существовать до `Start()`.
- Использовать `Start()` для:
  - инициализации, которая зависит от других объектов на сцене.
  - генерации уровня, спавна и подготовки библиотек.

## Работа с общими данными между сценами
- Хранить постоянные данные в `DungeonManager` (или другом менеджере) и помечать его `DontDestroyOnLoad`.
- Перед использованием внешних данных проверять `Instance != null` и иметь фолбэк.

## Работа со списками и ссылками
- Всегда проверять индексы и `null` в списках, особенно при обращении к `_spellbook`.
- При сохранении данных в `DungeonManager` следить за размером списка (использовать `while (list.Count <= index)` перед присваиванием).

## Ошибки компиляции, которых избегаем
- Ошибки вида “Invalid token 'if' in class” означают, что логика вынесена за пределы метода.
- Ошибки “Top-level statements must precede namespace and type declarations” означают, что в файле есть код вне класса.

## Порядок работы
1. Сначала проверить компиляцию скриптов, исправить синтаксис и скобки.
2. Затем проверить ссылки между файлами/сценами (`Instance`, сериализуемые поля, prefabs).
3. После этого запускать Unity и проверять поведение.

## Комментарии
- Держать комментарии короткими и по делу; избегать дублирования логики.
